# WordPress AI 站長

**給你的 AI 一套「WordPress 站長」的判斷力。**

它知道什麼該做、什麼要先問你、什麼絕對不能碰。

## 這是什麼

不是外掛。不是 SaaS。不是又一個要你註冊帳號的服務。

它是一份 **1,100 行的行為規範**（一個 `SKILL.md` 檔），裝進你已經在用的 AI（Claude Code、Codex、Cursor、OpenCode），讓它在碰你的網站時，有一套像真站長一樣的規矩：

- 聽得懂「我的網站好像壞了」這種話，也知道下一步該問什麼
- 分得出「改個標題」和「刪掉資料庫」的差別
- 危險的事會先問你，不是先做
- 做不到的事會直接說做不到，不會裝懂
- 需要專人時，幫你整理好資料再讓你去找人

**它不提供算力，也不連你的網站。** 連線與操作靠你自己的 AI 和你授權的工具（例如 BrowserOS、SSH）。這份規範決定的是「怎麼做、該不該做」。

## 前提

| 項目 | 必要性 | 說明 |
|---|---|---|
| **WordPress 網站** | 必要 | 6.0 以上 |
| **Cloudways 主機** | 建議 | 完整功能需要。四層快取、伺服器層操作都建立在 Cloudways 上 |
| **其他主機** | 可用但受限 | cPanel、SiteGround、自架：WordPress 層的功能可用，快取與伺服器層做不到，站長會直說 |
| **支援 skill 的 AI** | 必要 | Claude Code、Codex、Cursor、OpenCode 等 |
| **BrowserOS neo** | 選配 | 沒有 SSH 時的手，讓你用瀏覽器介面操作後台。免費開源 |

> 用其他主機也能用。站長不會因為你不是 Cloudways 就少幫你，只是有些事它會直接說做不到。

### 方法一：跟你的 AI 說一句話（推薦）

把下面這句丟給你的 AI Agent，它會自己找到 skills 目錄並裝好：

# git clone ... ~/.codex/skills/wordpress-ai-webmaster      # Codex

## 實際效果

以下是真實對話，不是示意圖。

### 不懂技術的人說「網站壞了」

> **你：** 我的網站好像壞了，怎麼辦？
>
> **站長：** 你說的「好像壞了」對應的是 1，但我必須先講清楚：這個站長的第 1～4 項功能都還沒開放，現在只會回話。
>
> **影響：** 你的網站目前我幫不上忙，跟你自己看一樣。
>
> 如果你想要自己檢查，你可以先看這三件事就夠了：能不能打開、打開看到什麼、主機後台有沒有紅色警告。
>
> **需要我詳細解釋嗎？**

**它沒有裝懂，也沒有丟一堆指令給你。**

---

### 專業人士問技術問題

> **你：** wp-admin 回 500，error_log 顯示 PHP Fatal error: Allowed memory size exhausted
>
> **站長：** 這則訊息是「記憶體用盡」，但兩種完全相反的成因，處理方式相反：
> - 情況 A：上限設得太小
> - 情況 B：某個東西吃太多
>
> 先看 bytes 數字就能判斷：41943040 = 40M（WP 單頁預設）、134217728 = 128M（多數外掛建議）。
>
> **最後這段是重點：** 下一個要改的是 wp-config.php 裡的 `WP_MAX_MEMORY_LIMIT`，這個常數**不在我可以自行修改的既定清單內**，屬於需要另外明確設定、並經過二次確認的等級。**我不會擅自改它。**

**它知道自己的權限邊界，而且會說出來。**

---

### 你說「只給我看」

> **你：** 只給我看，不要改。我的網站有沒有問題？
>
> **站長：** 結論：現在還無法回答「有沒有問題」—— 我還沒連線，不能亂說。
>
> **影響：** 目前你的網站我碰不到。
>
> 你說的「只給我看，不要改」模式已開啟，**我不會動任何東西**。
>
> 產出會是一份「問題、影響、建議」的報告，不會動你的檔案。要動手的部分我會另外標示，**等你一句「可以動手了」**，才做。

## 它會做什麼

- ✅ 聽懂白話需求，複述一次確認你指的是什麼
- ✅ 把工作拆成步驟，先提案再問你要不要做
- ✅ 判斷每一件事的風險等級（G0 只讀 → G3 禁止）
- ✅ 危險操作前要求備份、列出將要改什麼、等你同意
- ✅ 用比喻解釋技術問題（快取像門口的展示品，換了但展示的還是舊的）
- ✅ 判斷不出你的技術程度時，預設當「不懂技術」處理
- ✅ 做不到時直接說，並幫你整理交接資料
- ✅ 記住你設定的「只看不改」模式，直到你說解除

## 它不會做什麼

- ❌ 不會自己連你的網站（要靠你的 AI 與你授權的工具）
- ❌ 不會在你沒同意時改任何東西
- ❌ 不會假裝已經修好了
- ❌ 不會承諾 SEO 排名或 AI 搜尋曝光成效
- ❌ 不會在對話裡跟你索取密碼

## 安全設計

### 七層安全網

每一個會寫入網站的操作，都必須依序走完：

1. **備份** — 匯出資料庫、打包檔案。失敗就換方案，四種都失敗才進入風險說明
2. **dry-run** — 列出將要改的具體內容，不接受「優化 SEO」這種模糊說法
3. **確認** — 依風險等級取得你的明確同意
4. **可逆標記** — 每一項都標明「可逆」或「不可逆」
5. **staging 優先** — 高風險操作先測試站
6. **audit log** — 每個動作留一行紀錄，只增不改
7. **回滾** — 失敗自動還原，還原失敗立即停止並交你手動步驟

### 操作分級

| 級別 | 意思 | 站長怎麼做 |
|---|---|---|
| **G0 只讀** | 不改任何東西 | 直接執行 |
| **G1 可逆變更** | 改內容但能還原 | 提案後等你確認 |
| **G2 高風險** | 改檔案、外掛、主題 | 必須明確同意 + 備份 + staging |
| **G3 禁止** | 不可逆或會毀站 | 預設拒絕，除非你用自己的話二次明確要求 |

### G3 的具體清單

直接寫資料庫、刪 wp-content、改 wp-config 的資料庫憑證與安全金鑰、更換主題、停用全部外掛、重設資料庫、刪 Cloudways server。

**而且 wp-config.php 是封閉規則**：只允許四個特定的 `define()` 常數走 G2，其餘一律 G3。因為 wp-config 出錯是整站白屏，連後台都進不去。

### 弄壞了會怎樣

站長會**先備份才動手**，失敗自動回滾。如果真的回滾失敗，它會立即停止所有動作，並給你一份手動還原步驟（含備份識別碼與還原順序）。

## 還需要裝什麼

**只有一樣：BrowserOS neo。**

沒有 SSH 的時候，它是站長的手 —— 讓 AI 用你的瀏覽器登入狀態操作網站後台。

| | |
|---|---|
| 費用 | 免費、開源（AGPL-3.0） |
| 帳號 | 不需要，不需要 API key |
| 下載 | https://www.browseros.com/download/ |
| 特性 | 獨立瀏覽器，跟 Chrome 並存；首次開啟可一鍵匯入 Chrome 的書籤與密碼 |

裝好後開一次，它會自動偵測你電腦上的 Claude Code / Codex / Cursor，按一下就能連接，不需要改設定檔。

**其他都是授權，不是安裝：**

- WordPress 授權 → 在後台產生一組「應用程式密碼」
- 主機授權 → 給一組 SSH 金鑰或 Cloudways API Key

## FAQ

**Q：免費嗎？**
是，MIT 授權，永久免費。原始碼全部公開。

**Q：需要會寫程式嗎？**
不需要。站長預設假設你不懂技術，會用白話和比喻說明。你可以隨時說「講詳細一點」切換成技術模式。

**Q：一定要用 Cloudways 嗎？**
不用。但四層快取的自動消退、伺服器層操作（重啟、SSL、備份還原）只有在 Cloudways 上才做得到。其他主機它會直接告訴你哪幾項不行。

**Q：它會自己改我的網站嗎？**
不會。每一個寫入操作都要你同意，而且會先列出「將要改什麼」讓你確認。

**Q：如果它改壞了怎麼辦？**
七層安全網的第一層就是備份，失敗會自動回滾。你也可以在事前要求「先備份再做」。

**Q：支援哪些 AI？**
Claude Code、Codex、Cursor、OpenCode，以及任何支援 `SKILL.md` 格式的 Agent。

**Q：跟一般叫 AI 幫我改網站有什麼不同？**
一般 AI 會直接給你指令或直接動手。這個 skill 給它的是「判斷力」：什麼該做、什麼要先問、什麼絕對不能碰，以及出問題時怎麼收拾。

**Q：為什麼叫「站長」？**
因為它要模擬的不是「工具」，是「一個幫你顧網站的人」。
